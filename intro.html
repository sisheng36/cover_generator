core capabilities

一个工具，打通入库后的整条链路

从 Emby 新入库的那一刻开始，封面、通知和统计都由 Cover Generator 接管。

媒体库封面生成

拉取媒体库海报，按单图、多图等风格自动合成统一封面；支持中英文自定义媒体库名称，保持整个媒体库视觉整齐。

多风格 自定义标题 手动上传

Webhook 新入库联动

Emby 新电影或剧集入库后自动触发封面更新；同一媒体库短时间内的连续入库会自动合并窗口，避免重复刷新。

library.new 窗口合并 自动刷新

Telegram 入库通知

新入库、播放、登录等事件即时推送到 Telegram；剧集连续入库自动聚合成一条消息，配合 TMDB 补全评分、类型和简介。

聚合消息 TMDB 多事件

入库统计总览

近 30 天每日入库柱状图、今日 / 近 7 天 / 峰值统计，以及最新 32 个媒体的海报墙，入库情况一目了然。

30 天窗口 海报墙 峰值统计

定时任务

按 Cron 表达式定时为选中的媒体库更新封面，也可以一键生成全部或部分媒体库，让封面始终与内容同步。

Cron 手动生成 全量刷新

自托管与数据自主

Go 编写、Docker 一键部署，配置和统计数据都保存在本地 /data 目录，不依赖任何第三方服务，适合家庭媒体中心。

Go Docker 本地持久化

why cover-generator

为什么值得用 Cover Generator

不是为了堆功能，而是把媒体库入库后最常做的事，做成一站式的自动化闭环。

✓

自动闭环，少一次手工操作

新媒体入库 → 封面联动 → Telegram 通知 → 统计记录，全链路自动完成。

✓

通知不刷屏

剧集多集连续入库会聚合成一条消息；同一媒体库联动刷新也有窗口期合并。

✓

轻量、可迁移

Go 编译为原生二进制，空闲时内存占用明显低于 PHP 等传统服务端方案；配合 Docker Compose，配置与数据都在本地目录，随时备份和迁移。

✓

中文体验优先

界面、通知文案和自定义媒体库名称都对中文友好，适合家庭媒体中心使用。

✓

灵活可控

媒体库、封面风格、通知事件、统计窗口和定时策略都可以按自己的习惯配置。

deploy / quick start

部署与快速开始

Docker Compose 一键启动，随后在 Emby 后台把 Webhook 指向 Cover Generator 即可。

1 · Docker Compose 部署

将下面配置保存为 docker-compose.yml，在项目目录执行 docker compose up -d，随后打开 http://localhost:8055 即可进入控制台。

docker-compose.yml
# docker-compose.yml services: cover-generator: image: ghcr.io/sisheng36/cover_generator:latest container_name: Cover-Generator network_mode: host ports: - "8055:8055" volumes: - ./data:/data environment: - TZ=Asia/Shanghai restart: always

提示：使用 network_mode: host 时服务会直接监听宿主机 8055；ports 映射可按实际网络模式保留或调整。

2 · 配置 Emby Webhook

在 Emby 的 Webhook 插件中新增通知地址，按下面的参数填写即可开始联动。

请求地址 http://127.0.0.1:8055/webhook/emby
内容类型 application/json
触发事件 媒体库 → 已添加新媒体

提示：127.0.0.1 仅适用于 Emby 与 Cover Generator 同机部署；跨设备请填写 Cover Generator 的实际内网地址，并保持端口仅内网可访问。

webhook
# Emby Webhook 配置 POST http://127.0.0.1:8055/webhook/emby Content-Type: application/json 事件: 媒体库 → 已添加新媒体

安全提示

部署完成后，请将 Cover Generator 的 8055 端口纳入防火墙，仅允许内网访问。控制台中保存了 Emby API Key，如果把端口暴露到公网，可能导致 APIKey 泄露并带来安全损失。

开发调试时如果希望保持端口可访问，也请确保只在局域网内访问，不要把端口映射或开放到公网。
